> 选题：AI 智能面试官与人才评估系统（见 `docs/任务书原文.txt`）
> 项目根目录：`D:/26实习/SITAS` ｜ 周期：4 周 ｜ 团队：3 人 ｜ 借助 AI 助手（Claude Code + DeepSeek）

## 1. 项目目标（任务书要点）

面向大学生求职训练、校园招聘模拟和岗位能力评估，构建 AI 智能面试官系统。覆盖 5 大任务：

| # | 任务 | 说明 |
|---|---|---|
| 1 | 简历解析与岗位画像 | 抽取教育经历、项目经历、技能关键词、岗位要求、能力维度 |
| 2 | 岗位与面试题知识库 | 岗位说明、企业资料、常见题库、评分标准、优秀回答样例检索 |
| 3 | AI 面试 Agent | 自动生成问题/追问/评分/改进建议，调用招聘数据 SQL Agent 与流式语音面试工具 |
| 4 | 候选人端 | 简历上传、岗位选择、文字/语音面试、答题记录、评分反馈、报告查看 |
| 5 | HR/教师后台 | 企业、岗位、候选人、面试官、题库、面试记录管理 |

三类用户：**学生（候选人）**、**HR/教师**、**管理员**。

## 2. 统一环境约定（三人必须一致）

| 项 | 约定 | 说明 |
|---|---|---|
| Python | **3.11** | 三台机器一致 |
| 操作系统 | Windows 11 | — |
| 开发工具 | VSCode + Claude Code（对接 DeepSeek API） | 统一提示词见 `docs/提示词/` |
| Web 后端 | FastAPI + Uvicorn | 入口 `backend/app/main.py` |
| 数据库 | SQLite | 文件 `data/sitas.db`，零配置，无需装数据库服务 |
| ORM | SQLAlchemy 2.0 | 模型在 `backend/app/models/` |
| 参数校验 | Pydantic v2 | 模型在 `backend/app/schemas/` |
| 大模型 | DeepSeek API（OpenAI 兼容） | 用 `openai` SDK，base_url=`https://api.deepseek.com`，key 放 `.env` |
| RAG 检索 | BM25（`jieba` + `rank-bm25`） | 离线可用，不依赖向量库/embedding API |
| 前端 | Vue3（CDN）+ Bootstrap5 | 无 Node 构建工具，由 FastAPI 托管静态页 |
| 语音 | faster-whisper（可选，本地 CPU） | 未安装时语音走占位、面试仍可文字进行 |
| 版本控制 | Git | **强烈建议**建 GitHub/Gitee 私有仓库，分支协作 |
| 字符编码 | UTF-8 | — |
| 密钥管理 | `.env`（参考 `.env.example`） | 禁止入库、禁止写死在代码 |

**环境安装（每人执行一次）**：
```bash
cd D:/26实习/SITAS
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # 填入 DEEPSEEK_API_KEY
python -m backend.scripts.init_db     # 建表 + 演示数据
uvicorn backend.app.main:app --reload --port 8000
```
启动后访问 `http://127.0.0.1:8000/`（前端）、`/docs`（API 文档）。

## 3. 技术架构

```
┌──────────────┐      REST /api/*       ┌───────────────────┐
│  前端(成员C)   │ ────────────────────▶ │ 业务后端(成员B)      │
│ Vue3+Bootstrap│ ◀──────────────────── │ FastAPI + 路由      │
└──────────────┘   统一JSON响应           │  + SQLite/ORM       │
                                        └────────┬──────────┘
                                                 │ 调用服务层函数
                                        ┌────────▼──────────┐
                                        │ AI服务层(成员A)      │
                                        │ services/ + rag/   │
                                        └────────┬──────────┘
                                                 │ 调用
                                        ┌────────▼──────────┐
                                        │ DeepSeek API /     │
                                        │ 知识库(data/knowledge)│
                                        └───────────────────┘
```

**依赖方向**：前端(成员C) → 业务后端API(成员B) → AI服务层(成员A) → LLM/知识库。
数据模型 `models/`、响应格式 `schemas/` 由成员B维护，成员A只读类型做开发。

## 5. 接口契约（成员间协作的核心）

### 5.1 统一响应格式（成员B 定义，成员C 使用）

```json
{ "code": 0, "message": "success", "data": { } }
```
错误码：`1001` 参数错误 ｜ `1002` 资源未找到 ｜ `1003` 服务器错误。

### 5.2 成员A 提供给成员B 的服务函数签名（B 的 API 依赖）

| 函数 | 签名 | 返回 |
|---|---|---|
| 简历解析 | `resume_parser.parse_resume(text) -> dict` | 画像 dict |
| 岗位画像 | `job_profiler.build_job_profile(job) -> dict` | 画像 dict |
| 面试编排 | `interview_agent.plan_interview(job_profile, resume_profile, categories=None) -> list[dict]` | 问题序列 |
| 追问 | `interview_agent.generate_followup(context, job_profile) -> dict` | `{question, reason}` |
| 评分 | `interview_agent.evaluate_answer(question, answer, category, expected_points, evidence) -> dict` | `{score, feedback, improvement, missing_points, evidence}` |
| 评分汇总 | `scoring.aggregate(scores) -> dict` | 总分/维度分 |
| 报告 | `report.generate_report(data) -> dict` | 完整报告 |
| SQL 查询 | `sql_agent.ask(question) -> dict` | `{sql, columns, rows, explanation}` |
| 语音转写 | `voice.transcribe(audio_path) -> str` | 文本 |
| 检索 | `rag.knowledge_base.search(query, top_k) -> list[dict]` | 文档+依据 |

### 5.3 成员B 提供给成员C 的 REST API（C 的页面依赖）

见各 `api/*.py` 文件顶部注释，其中 `api/candidate.py` 是最全的一份契约。
**改动路径/参数必须发到群里通知成员C。**

## 7. 协作流程与约定（GitHub 仓库）

**仓库**：https://github.com/DavidChristof/SITAS_InternshipProgram

1. **首次加入**：`git clone https://github.com/DavidChristof/SITAS_InternshipProgram.git`，并设置 `git config user.name/user.email` 为自己的 GitHub 身份。
2. **固定功能分支**：成员A 用 `feature/A-ai-core`，成员B 用 `feature/B-backend`，成员C 用 `feature/C-frontend`。各自在分支上开发，**只 `git add` 自己负责的目录**。
3. **提交流程**：`git pull --rebase origin main` 同步 → `git commit -m "[模块] 说明"` → `git push -u origin 自己的分支` → 完成后合并回 `main`。
4. **提交信息**：`[模块] 说明`，如 `[候选人API] 新增简历上传接口`。
5. **冲突处理**：`git pull --rebase` 冲突时，打开文件保留双方代码 → `git add` → `git rebase --continue`。
6. **跨域改动**：改到别人拥有的文件，先告知再动手，并在 PR 说明理由。
7. **每日同步**：微信/群 10 分钟同步进度与阻塞点。
8. **演示兜底**：保证"无 API key 也能演示"——A 的降级逻辑 + B 的演示数据 + C 的静态页面。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| DeepSeek 调用超时/限流 | 服务层全部 try/except 降级；重试 1 次；超时设 30s |
| 三人同时改数据库字段 | models 归 B 一人改；A/C 只读 |
| 前端与后端字段对不上 | 统一响应格式 + api.py 顶部契约 + /docs 联调 |
| 语音识别慢/装不上 | 语音为可选项，文字面试保底 |
| 演示环境没网 | 所有前端用 CDN，提前把 Vue/Bootstrap 本地化一份（`frontend/static/vendor/`） |
