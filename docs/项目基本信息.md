## 2. 项目背景与目标

面向**大学生求职训练、校园招聘模拟和岗位能力评估**场景，构建 AI 智能面试官系统。系统需覆盖：简历解析、岗位知识库检索、结构化面试、多轮追问、回答评分、反馈报告、面试记录和后台题库管理，覆盖大模型、RAG、Agent、前端交互和后端管理模块。

**核心业务闭环**：`简历上传 → 简历解析 → 岗位选择 → 知识库检索 → AI 生成问题 → 候选人回答 → AI 追问与评分 → 生成面试报告 → 保存记录`。

**三类用户**：
1. **候选人（学生）**：注册登录、上传简历、选岗位、文字/语音面试、看报告与历史。
2. **HR/教师**：企业管理、岗位管理、候选人管理、面试官管理、题库管理、面试记录查看。
3. **管理员**：后台全局管理（含用户/权限）。

## 5. 系统架构

### 5.1 总体分层

```
┌─────────────────────────────────────────────┐
│  前端层（frontend/index.html）                │
│  Vue3 CDN + Bootstrap：候选人端 + 后台管理      │
└──────────────────┬──────────────────────────┘
                   │ RESTful API（JSON，{code,message,data}）
┌──────────────────▼──────────────────────────┐
│  业务接口层（backend/app/api/，成员B）        │
│  /api/candidate /api/interview /api/admin   │
│  /api/knowledge                              │
└──────────────────┬──────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────┐
│  AI 服务层（backend/app/services/，成员A）    │
│  resume_parser / job_profiler / interview_  │
│  agent / scoring / report / sql_agent /     │
│  voice                                       │
│  ⚙ 核心铁律：不抛异常，LLM 不可用降级为规则结果 │
└───────┬──────────────┬──────────────────────┘
        │              │ BM25 检索
┌───────▼──────┐  ┌────▼─────────────────────┐
│ SQLite 业务库 │  │ RAG 知识库（data/knowledge）│
│ (data/sitas.db)│ │ jieba + rank-bm25 离线索引 │
└──────────────┘  └──────────────────────────┘
```

### 5.2 关键设计原则

1. **降级优先（核心铁律）**：所有服务函数**绝不抛异常**；LLM（DeepSeek）不可用时，自动降级为规则结果，保证无 API Key 也能演示完整流程。
   - 简历解析：规则提取（邮箱/电话/学历/技能词库）先行，LLM 补全。
   - 出题：优先复用知识库题库 → 其次 LLM 生成 → 最后通用模板题。
   - 评分：`_rule_score` 按"要点命中率 + 回答完整度"给分。
   - 报告：按维度得分生成优缺点与录用建议。
   - SQL Agent：无 key 时按关键词返回内置规则 SQL。
2. **分层清晰**：服务层纯逻辑、不含路由；成员B 的 API 层负责数据库会话与状态机；前端只调 REST 接口。
3. **RAG 证据链**：每道面试题附带 `evidence`（知识库检索依据），评分可关联依据。

## 6. 核心业务流程（面试主流程）

```
候选人上传简历
   └→ resume_parser.parse_resume(文本)        解析出结构化画像
候选人浏览岗位、创建面试
   └→ job_profiler.build_job_profile(岗位)    生成岗位画像
面试开始
   └→ interview_agent.plan_interview(岗位画像, 简历画像)
         生成 5 个环节问题序列，每轮 {round_no, category, question, expected_points, evidence}
候选人逐题作答
   └→ interview_agent.evaluate_answer(问题, 回答, 环节, 要点)
         返回 {score(0-100), feedback, improvement, missing_points, evidence}
可追问
   └→ interview_agent.generate_followup(历史问答, 岗位画像)
         返回 {question, reason}
面试结束
   └→ scoring.aggregate(全部评分)              {total_score, dimension_scores, answer_count}
   └→ report.generate_report(面试数据)         完整报告（含 radar_scores / 优缺点 / 录用建议）
```

**5 个面试环节**（`DEFAULT_ROUNDS`）：`self_intro`（自我介绍）→ `project`（项目深挖）→ `technical`（专业能力）→ `behavioral`（行为面试）→ `reverse`（候选人反问）。

**5 个能力维度**（`scoring.CATEGORY_DIMENSION`）：

| 环节 | 维度 |
|---|---|
| self_intro | 表达能力 |
| project | 项目实践 |
| technical | 专业能力 |
| behavioral | 综合素质 |
| reverse | 求职动机 |

## 8. 接口契约

### 8.1 统一响应格式（成员B 定义）

```json
{ "code": 0, "message": "success", "data": { } }
```
业务错误码：`1001` 参数错误 ｜ `1002` 资源未找到 ｜ `1003` 服务器错误（见 `backend/app/schemas/__init__.py` 的 `ok()` / `fail()`）。

### 8.2 AI 服务层函数（成员A 提供，成员B 调用）

| 函数 | 签名 | 返回关键字段 |
|---|---|---|
| 简历解析 | `resume_parser.parse_resume(text) -> dict` | name/email/phone/degree/years_experience/education/projects/skills/internships/summary/rule_only |
| 岗位画像 | `job_profiler.build_job_profile(job) -> dict` | title/core_skills/capability_dimensions/interview_focus/suggested_rounds |
| 面试编排 | `interview_agent.plan_interview(job_profile, resume_profile, categories=None) -> list[dict]` | 每轮 `{round_no, category, question, expected_points, evidence}` |
| 追问 | `interview_agent.generate_followup(context, job_profile) -> dict` | `{question, reason}` |
| 评分 | `interview_agent.evaluate_answer(question, answer, category, expected_points, evidence) -> dict` | `{score(0-100), feedback, improvement, missing_points, evidence}` |
| 评分汇总 | `scoring.aggregate(scores) -> dict` | `{total_score, dimension_scores, answer_count}` |
| 报告 | `report.generate_report(data) -> dict` | total_score/level/dimension_scores/**radar_scores**/overall_comment/strengths/weaknesses/suggestions/hire_recommendation/answers/generated_at |
| SQL 查询 | `sql_agent.ask(question) -> dict` | `{question, sql, columns, rows, explanation}` |
| 语音转写 | `voice.transcribe(audio_path) -> str` | 转写文本（不可用返回空串） |
| 检索 | `rag.knowledge_base.search(query, top_k=5) -> list[dict]` | `[{id, title, content, source, score, meta}]` |

> 报告中的 `radar_scores` 已补全 5 个维度（未考维度记 0），供前端雷达图使用。
> `sql_agent.ask` 采用白名单安全校验：仅允许单条 SELECT、拒绝堆叠语句/注释/危险关键字/非白名单表列，无 key 时按关键词返回规则查询。

### 8.3 REST API（成员B 实现，当前进度）

已实现：`GET /api/candidate/jobs`、`GET /api/interview/ping`、`GET /api/admin/ping`、`GET /api/knowledge/ping`、`GET /health`、`GET /`（前端页）。

规划中（`api/interview.py` 顶部注释）：`POST /api/interview/{id}/start`（调 `plan_interview` 返回第一题）、`POST /api/interview/{id}/answer`（提交回答→返回 `{score, feedback, next_question|END}`）、`GET /api/interview/{id}/report`（调 `report.generate_report`）。
