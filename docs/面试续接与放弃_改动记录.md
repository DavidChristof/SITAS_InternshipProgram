## 1. 背景与问题

此前面试状态机为 `pending → running → finished`，存在两个缺口：

1. **中途退出后无法续接**：running 的面试没有接口能查出"当前到第几题、题目是什么"，前端也无续接入口，记录永远停在「进行中」；
2. **无法放弃**：未完成的面试只能一直挂着，没有"放弃/作废/中断"的处理。

答辩可能被问及"学生中途退出怎么办"，属于明显不完善的点，故补齐。

## 2. 方案

扩展状态机为 **`pending → running → finished | abandoned`**，新增两个接口 + 前端入口：

| 能力 | 实现 |
|---|---|
| **续接** | `GET /api/interview/{id}/state` 返回当前状态；running 时带当前未答题（`current_round` 对应题目），前端进入面试页先查 state：pending→start、running→恢复题目/进度/面试官继续答、finished→跳报告、abandoned→提示已放弃 |
| **放弃（作废）** | `POST /api/interview/{id}/abandon` 将 pending/running 置为 `abandoned` 终态；作废后无法继续作答、无法生成报告、不可重复放弃 |
| **前端入口** | 面试对话页新增「🚫 放弃本次面试（作废）」按钮；候选人历史记录中 pending/running 显示「继续面试」，abandoned 显示「已放弃」 |

## 4. 验证结果

- ✅ 状态机：创建(pending) → start(running) → 答 1 题后 `state` 返回第 2 题（`round_no=2`、题目存在、`total_rounds=5`）→ 续接数据正确
- ✅ 放弃：pending/running → `abandoned`；放弃后 answer/report/重复 abandon 全部拒绝（`code=1001`）；已完成面试不可放弃
- ✅ 前端渲染（headless Edge）：running 面试页显示"欢迎回来！继续上次未完成的面试，当前是第 1 题"+ 题目 + 放弃按钮 + 作答区；abandoned 面试页显示"🚫 面试已放弃（作废）"卡片、作答区消失
- ✅ 回归：`pytest backend/tests/ -v` → **148 passed**

## 5. 答辩口径

> 演示：历史记录里「进行中」的面试点**继续面试** → 对话页提示"欢迎回来！继续上次未完成的面试，当前是第 X 题"并恢复题目继续作答；中途想放弃则点**放弃本次面试** → 记录变为「已放弃」且不可恢复、不生成报告。
>
> 话术：**面试状态机覆盖了完成、续接、放弃三种结局**——学生中途退出可随时从上次题目继续，也可以主动放弃作废，后台筛选也能看到"已放弃"记录，流程完整可演示。
