## 一、开场（成员A，约 1 分钟）

> 各位老师好！我是 XX（成员A），是我们五人项目小组的组长，今天由我担任主讲，带大家一起演示我们的项目——**AI 智能面试官与人才评估系统**，简称 SITAS。

> 一句话介绍：**系统模拟一个真实的 AI 面试官——学生上传简历后，系统自动生成 5 个环节的结构化问题，逐题问答、实时评分，最终输出一份带雷达图的评估报告；HR 和管理员通过后台完成完整的招聘数据管理。** 后面我们五个人会依次介绍各自负责的模块，最后配合系统做现场演示。

## 二、项目背景与需求分析（成员A，约 1 分钟）

> 为什么做这个系统？校园招聘里，**求职者缺少低成本、可反复练习的面试训练方式，用人方缺少标准化的能力评估手段**。我们面向大学生求职训练、校园招聘模拟与岗位能力评估三个场景。

> 按照需求文档，系统服务**三类用户**，功能边界清晰隔离：
> - **学生**：上传简历 → 选岗 → 与 AI 面试官对话 → 查看评估报告；
> - **HR/教师**：维护企业/岗位/题库，查看候选人档案与面试记录；
> - **管理员**：在 HR 之上，额外拥有面试官管理和系统管理。
>
> （提示：点身份选择页三张卡片示意边界）

## 三、项目架构（成员A，约 1.5 分钟）

> 系统采用**分层架构**，我重点讲后端与 AI 侧（前端在分工环节由 C/D 补充）。

**架构总览（可画图/PPT 展示）：**

```
┌─────────────────────────────────────────────┐
│  前端展示层  Vue3(CDN) + Bootstrap5           │
│  身份门面：学生 / HR教师 / 管理员              │
│  候选人端 · 面试对话 · 结果报告 · 后台管理      │
└──────────────┬──────────────────────────────┘
               │ HTTP / JSON（{code,message,data}）
┌──────────────▼──────────────────────────────┐
│  API 层  FastAPI                              │
│  /api/candidate  /api/admin  /api/interview  │
│  /api/knowledge（检索/建索引）                 │
└──────────────┬──────────────────────────────┘
┌──────────────▼──────────────────────────────┐
│  服务层（AI 核心）                             │
│  简历解析 → 岗位画像 → 面试Agent（出题/追问/评分/│
│  报告）→ SQL Agent → 语音转写 → 降级引擎        │
└──────────────┬──────────────────────────────┘
┌──────────────▼──────────────────────────────┐
│  知识库层（RAG）  jieba + BM25 离线检索          │
│  岗位JD · 企业资料 · 题库 · 评分标准 · 回答样例   │
└──────────────┬──────────────────────────────┘
┌──────────────▼──────────────────────────────┐
│  数据层  SQLite + SQLAlchemy 2.0              │
└──────────────────────────────────────────────┘
```

> 三个关键设计：
> 1. **全链路降级**：所有 AI 服务在无 API Key 或调用失败时自动降级为规则引擎，保证演示不断链；
> 2. **证据链**：面试出题与评分都关联知识库检索依据，回答有据可查；
> 3. **状态机控制**：面试流程 `待开始 → 进行中 → 已完成/已放弃`，中途退出可续接、可放弃作废。

## 四、项目技术栈（成员A，约 1 分钟）

| 层次 | 技术 | 一句话说明 |
|---|---|---|
| 后端 | **FastAPI + SQLAlchemy 2.0 + SQLite + Pydantic v2** | 异步高性能，统一 `{code,message,data}` 接口规范 |
| AI 核心 | **DeepSeek 大模型**（openai SDK 统一封装） | 超时/重试/JSON 健壮解析，密钥走环境变量 |
| RAG 知识库 | **jieba 分词 + BM25 离线检索** | 无向量库、无外网依赖，演示可离线 |
| 语音 | **faster-whisper 本地转写**（可选） | 录音转文字，失败自动降级文字作答 |
| 前端 | **Vue3(CDN) + Bootstrap5** | 无 Node 构建工具，原生 canvas 画雷达图 |
| 测试 | **pytest，148 条用例** | 覆盖全链路，无 key 离线全部可跑通 |

> 强调：**我们坚持"降级优先"与"离线可用"**——前端资源本地化、AI 有规则兜底，现场断网也能完整演示。

## 五、五人分工介绍（全员，约 2.5 分钟）

> 成员A 起头，然后按顺序请每位成员介绍自己负责的部分，每人约 30~40 秒。

**成员A（组长，主讲）—— AI 核心 + 知识库**
> 我负责系统的 AI 核心与知识库检索：包括简历解析与岗位画像、RAG 知识库建设、五环节面试 Agent 编排（出题/追问/评分/报告）、SQL Agent 与语音转写，以及总体架构与需求分析文档。核心思路是把面试做成一个"感知—规划—行动—评估—总结"的 Agent 流程。

**成员B —— 业务后端 + 数据库**
> 我负责业务后端接口与数据库：实现了候选人端、后台管理、面试流程三类接口，设计了六张业务表与面试状态机（pending → running → finished / abandoned），并保证所有接口遵循统一的响应格式与接口契约。

**成员C —— 前端候选人端 + 身份门面**

**成员D —— 前端后台 + 测试用例**
> 我负责前端后台管理页与测试用例设计：实现企业、岗位、候选人、面试官、题库、面试记录六类管理页面与 Mock 数据兜底机制，并参与了需求分析与文档整理，保证后台功能完整可用。

## 六、现场演示（成员A 主讲 + 全员配合，约 4 分钟）

> 演示节奏：一边操作一边讲，每步一句关键话术。

**步骤 1 · 身份选择（10 秒）**
> "打开系统首先选择身份——学生、HR/教师、管理员三类入口，刷新后身份保持。"

**步骤 2 · 学生 · 上传简历（30 秒）**
> 操作：学生 → 上传简历 → 选「示例简历_张三」。
> "系统解析简历生成候选人档案——教育经历、技能关键词、项目经验都抽取出来了，同时生成岗位画像。"

**步骤 3 · 选岗 + 指定面试官（20 秒）**
> 操作：岗位大厅选「Java 后端开发工程师」，下拉选面试官「王老师」。
> "候选人可选岗，还能指定本次面试官——面试官名册不只是名单，每场面试都有归属。"

**步骤 4 · 面试对话 · 5 环节（1.5 分钟）**
> 操作：开始面试 → 依次回答 3~4 题（自我介绍→项目→专业，每题展示评分反馈）。
> "AI 面试官按 5 个环节出题，每题实时评分、给改进建议；题目来自岗位画像 + 简历 + 知识库检索的证据链。"
> （可选亮点）"这里我演示一下语音作答——点「语音」录音，系统本地 faster-whisper 转成文字填入答题框。"（若时间紧可略过）

**步骤 5 · 结果报告（30 秒）**
> 操作：完成面试 → 查看结果报告。
> "报告含总分、等级、**五维能力雷达图**（canvas 原生绘制）、优缺点、录用建议与逐题复盘。"

**步骤 6 · 历史记录：继续 / 放弃（20 秒）**
> 操作：历史记录 → 点进行中的「继续面试」→ 返回上一题继续；再演示「放弃本次面试」→ 状态变已放弃。
> "中途退出可随时从上次题目继续，也可主动放弃作废——状态机覆盖完成/续接/放弃三种结局。"

**步骤 7 · HR/管理员后台（30 秒）**
> 操作：切 HR → 后台 5 个管理页（无面试官管理）；切管理员 → 面试官管理 + 系统管理。
> "HR 视角没有面试官管理；管理员拥有全部 7 个入口和系统管理的数据概览。五类业务对象完整增删改查。"

## 附 2：评委可能问的问题（Q&A 预案）

1. **"RAG 检索用什么算法？"** → jieba 分词 + BM25 稀疏检索，离线可用、够用且快；向量检索为可扩展方向。
2. **"面试官管理有什么意义？"** → 名册让每场面试有归属（候选人选岗指定面试官，对话/报告体现）；账号登录+数据隔离为方案B 后续演进。
3. **"评分公平性怎么保证？"** → 评分锚定知识库评分标准 + 每题要点（expected_points），规则+大模型双重保障，可解释可复现。
4. **"无 API Key 时系统还能用？"** → 是，所有 AI 服务降级为规则引擎，148 条测试全程离线跑通，这是"降级优先"铁律的验证。
5. **"为什么不用 Node 构建？"** → 答辩演示强调离线与简单部署，Vue3 CDN + Bootstrap 本地化即可完整运行。
6. **"五人怎么分工、怎么协作？"** → 固定功能分支 + 目录所有权 + 接口契约 + 代码评审，合流 main，避免互相覆盖。
7. **"语音转写怎么实现的？"** → 前端 MediaRecorder 录音上传，后端 faster-whisper 本地转写，失败自动降级文字作答。
8. **"数据库为什么用 SQLite？"** → 面向演示与教学场景的单机存储，SQLAlchemy 已抽象，生产可平滑迁移。
