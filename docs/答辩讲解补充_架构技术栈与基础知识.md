# 答辩讲解补充：架构 · 技术栈 · 基础知识

> 用途：配合《答辩稿.md》使用。本文件教你怎么把架构图和技术栈"讲明白"，并补充答辩问答需要的前后端/Agent/RAG 等基础概念。
> 用法：每段先给"讲稿"（照着说），再给"大白话"（自己理解），最后给"一句话"（被追问时的收尾）。

---

## 一、项目架构图：逐层讲解文稿

### 讲解总思路（3 句话搭框架）

先给评委一个整体心智模型：

> "我们的系统是**分层架构**：用户在前端操作 → 前端把请求通过 HTTP 发给后端 API → API 调用 AI 服务层 → 服务层查知识库、调大模型 → 结果一层层返回，最后落库保存。**每一层只做自己的事，通过明确接口通信**，这样模块清晰、可单独测试、可替换。"

> 大白话：就像一家餐厅——**前端是菜单和点餐台**，**API 是服务员**，**服务层是后厨**，**知识库是冰箱**，**大模型是外聘的大厨**，**数据库是账本**。菜（结果）做好后服务员端给顾客。

---

### 第一层：前端展示层（Vue3 + Bootstrap5）

**讲稿：**
> "最上层是前端展示层，负责用户看到和操作的一切。我们用 Vue3 配合 Bootstrap5 实现页面，没有引入 Node 构建工具，所有静态资源本地化，离线也能完整运行。前端按三类身份做了**身份门面**：学生看到候选人端，HR/教师和管理员看到后台，且按角色隐藏菜单。"

**一句话（追问）：** "前端只管展示和交互，不直接碰数据，所有数据都通过 HTTP 请求后端接口拿。"

---

### 第二层：API 层（FastAPI）

**讲稿：**
> "第二层是 API 层，相当于前后端之间的'翻译官'。它把前端发来的 HTTP 请求转给后端处理，再统一返回 `{code, message, data}` 格式的 JSON。我们按业务拆成四个模块：候选人端、后台管理、面试流程、知识库检索。"

**大白话：** 前端不直接访问数据库，而是调用 `/api/candidate/jobs` 这种"网址接口"。接口收请求、调服务、回 JSON。统一格式的好处是——前端写一个解析逻辑就能处理所有接口，出错时看 code 就知道哪类问题（1001 参数错/1002 未找到/1003 服务器错）。

---

### 第三层：服务层（AI 核心）

**讲稿：**
> "第三层是系统的核心——AI 服务层。它承载了所有业务与算法逻辑：简历解析、岗位画像、面试 Agent 编排（出题/追问/评分/报告）、SQL Agent、语音转写。**这一层的设计铁律是降级优先**：所有 AI 函数在大模型不可用时自动降级为规则引擎，保证流程不中断。"

**大白话：** 这是"大脑"。比如候选人回答一道题后，服务层会：拿题目要点 → 检索知识库证据 → 让大模型打分 → 降级时按规则打分 → 返回分数和反馈。

---

### 第四层：知识库层（RAG，jieba + BM25）

**讲稿：**
> "第四层是知识库层，也是我们 RAG 检索的实现。我们把岗位说明、企业资料、题库、评分标准、优秀回答样例五类文档，用 jieba 分词 + BM25 算法建了离线索引。面试出题和评分时，先从知识库检索最相关的片段，作为'证据链'提供给大模型，**让回答和评分都有据可查**。"

**大白话：** 大模型训练时不知道我们项目的专属知识（比如具体岗位 JD、公司资料），所以我们把知识放进自己的"冰箱"（知识库），要的时候按关键词捞出来喂给大模型。这就是"检索增强生成"。

---

### 第五层：数据层（SQLite + SQLAlchemy）

**讲稿：**
> "最底层是数据层，用 SQLite 存企业、岗位、候选人、面试官、题库、面试记录六类业务数据，通过 SQLAlchemy 2.0 这个 ORM 工具访问。面试状态机（待开始→进行中→已完成/已放弃）也在这层持久化。"

**一句话（追问）：** "为什么用 SQLite？——单机、零配置、适合演示场景；因为用了 SQLAlchemy 抽象，生产环境可平滑换 MySQL/Postgres。"

---

### 层间调用示例（背熟这个例子）

> 以"候选人点击『开始面试』"为例，完整链路：
> 1. 前端 `面试对话页` 发 `POST /api/interview/3/start`；
> 2. API 层校验面试存在、状态是 pending；
> 3. 调服务层 `plan_interview`：查岗位画像 + 简历 + **知识库检索证据** → 让 **DeepSeek 生成**第一题；
> 4. 服务层把 5 道题落库（数据层）；
> 5. 返回第一题给前端展示。
>
> 评委问"数据怎么流"就用这个例子讲。

## 二、技术栈逐个讲解文稿

### 后端

**FastAPI**
> 讲稿："一个 Python 的异步 Web 框架。选它是因为性能好（基于 ASGI 异步）、自动生成 Swagger 接口文档、配合 Pydantic 做类型校验，开发调试效率高。"
> 被追问："FastAPI 和 Flask 区别？" → "Flask 是同步 WSGI 轻量框架，需自己集成文档和校验；FastAPI 基于 ASGI 原生异步、自带文档、Pydantic 校验，适合高并发和快速迭代。"

**SQLAlchemy 2.0（ORM）**
> 讲稿："数据库访问层。用 Python 对象（类）映射数据库表，不用手写 SQL 就能增删改查。"
> 被追问："ORM 和原生 SQL？" → "ORM 开发快、防注入、可移植；但复杂查询性能不如原生 SQL。我们大部分用 ORM，性能敏感处看执行计划优化。"

**SQLite**
> 讲稿："文件型数据库，零配置、单文件，适合演示场景。"
> 被追问："生产能用吗？" → "并发写弱，但演示/教学足够；SQLAlchemy 已抽象，可迁移 MySQL/Postgres。"

**Pydantic v2**
> 讲稿："数据校验库。接口入参出参都定义成模型，自动校验类型、范围，非法请求直接报 1001。统一响应格式就是用它保证的。"

### AI 核心

**DeepSeek / openai SDK**
> 讲稿："大模型用 DeepSeek，通过 OpenAI 兼容的 SDK 调用，base_url 指向 `api.deepseek.com`。所有调用封装在一个 `llm.py`，统一做超时、重试、JSON 容错解析。"
> 被追问："为什么封装？" → "不散落各处调模型；集中处理超时/重试/解析，还便于无 key 时走规则降级。"

**提示词工程（Prompt）**
> 讲稿："为 5 个面试环节各写了一套提示词模板（自我介绍/项目深挖/专业/行为/反问），把岗位信息、简历素材、知识库证据拼进提示词，引导模型输出结构化 JSON。"
> 被追问："提示词怎么设计？" → "角色设定 + 任务 + 输入 + 输出格式约束（JSON）+ 评分维度，保证模型输出稳定可用。"

### RAG

**jieba 分词**
> 讲稿："中文没有空格，检索前先分词。jieba 是开源中文分词库，把'面试官'切成'面试/官'这样的词，才能做关键词检索。"

**rank-bm25（BM25 算法）**
> 讲稿："一个经典的信息检索排序算法。根据词频和文档长度给每个文档打分，返回最相关的若干篇。选它是因为离线、快、够用，不依赖外网和向量库。"
> 被追问："为什么不用向量检索？" → "向量检索需要嵌入模型和索引，离线环境部署重；BM25 对关键词类检索够用，是我们'离线可用'原则下的合理选择，向量检索是后续扩展方向。"

### 前端

**Vue3（CDN 引入）**
> 讲稿："前端框架，通过 CDN 的 script 标签引入，不装 Node、不跑构建。组件化 + 响应式数据驱动页面。"
> 被追问："CDN 和 npm 有什么区别？" → "npm 需要 Node 构建工具链；CDN 直接浏览器加载 JS 文件，我们把文件本地化了，所以离线也能跑。"

**Bootstrap5**
> 讲稿："CSS 框架，提供现成的栅格、按钮、弹窗组件，界面不用从零写样式。"

**原生 canvas 雷达图**
> 讲稿："报告页的五维能力雷达图用 HTML5 canvas 自己画，不依赖任何图表库，保证无外网也能渲染。"

### 测试

**pytest（148 条用例）**
> 讲稿："自动化测试框架。我们覆盖简历解析、出题、评分、报告、SQL Agent 安全校验、接口 CRUD、状态机等，148 条全部通过，且无 API Key 离线可跑——直接证明降级设计。"

## 三、基础知识补充（答辩问答用）

### 1. 什么是前端 / 后端？怎么配合？
> **前端**：用户看得见的部分——页面、按钮、输入框，负责"展示和交互"。
> **后端**：用户看不见的部分——接收请求、处理数据、调用算法，负责"逻辑和数据"。
> **配合方式**：前端通过 **HTTP 请求**（GET 拿数据 / POST 提交）调用后端的 **API 接口**，后端返回 **JSON 格式**的数据，前端拿到后渲染成页面。这个"双方约定好的接口格式"就叫**接口契约**。
> 项目例子：前端岗位大厅 GET `/api/candidate/jobs` 拿岗位列表 → 渲染成卡片。

### 2. 什么是 Web API / RESTful？
> **API** = 程序之间的接口（Application Programming Interface）。Web API 就是通过网址调用的接口，如 `GET /api/admin/enterprises`。
> **RESTful** 是一套设计风格：用 HTTP 方法表达操作——GET 查、POST 增、PUT 改、DELETE 删；资源用名词命名。我们后台 CRUD 接口就是 RESTful 风格。

### 3. 什么是数据库 / ORM？
> **数据库**：存数据的地方，按表组织。我们的六张表：企业/岗位/候选人/面试官/题库/面试记录。
> **ORM**（对象关系映射）：把数据库表映射成程序里的对象。写 `db.add(enterprise)` 就相当于插入一条记录，不用手写 SQL。

### 4. 什么是大模型 / LLM / API Key？
> **大模型（LLM）**：通过海量文本训练出来的语言模型，能理解并生成自然语言，如 DeepSeek、GPT。
> **API Key**：调用付费大模型的"钥匙"，放在 `.env` 环境变量里，不写进代码，避免泄露。
> **调用方式**：把一段文本（提示词）发给模型的 API，它返回生成的文本。我们在 `llm.py` 里封装了这一切。

### 5. 什么是提示词工程（Prompt Engineering）？
> 设计给大模型的"指令"叫提示词。写得好，模型输出就稳定、符合格式。
> 项目例子：面试评分提示词告诉模型"按评分维度打分，输出 JSON"，它就会返回 `{"score": 88, "feedback": "..."}` 这样的结构。

### 6. 什么是 RAG（检索增强生成）？
> **RAG = 先从自己的知识库检索相关内容，再把内容拼进提示词交给大模型生成回答。**
> 解决什么问题：大模型不知道你项目的专属知识（岗位 JD、企业资料），而且知识会过时。把知识放进自己的知识库，回答时"先查再答"。
> 项目例子：面试官问"请介绍贵公司"，系统先从 `companies/` 检索公司资料，作为证据给大模型，让它基于资料作答。

### 7. 什么是 Agent？本项目 Agent 体现在哪？
> **Agent（智能体）**：能"感知 → 规划 → 行动 → 评估"的自主系统。它不是一个单次调用，而是一个**有状态、会决策的流程**。
> 本项目的 Agent 化体现在（背熟这段）：
> - **感知**：简历解析 + 岗位画像 → 了解候选人是谁、岗位要什么；
> - **规划**：`plan_interview` 按 5 环节编排问题序列；
> - **行动 + 工具**：逐题提问、收集回答、调用 SQL Agent / 语音工具；
> - **记忆**：RAG 知识库检索的证据链；
> - **评估**：逐题评分、生成报告；
> - **状态控制**：状态机驱动整个循环推进。
> 一句话："我们把面试做成一个**编排式 Agent**——不是简单调一次大模型，而是记忆、规划、工具、评估齐备的完整循环。"

### 8. 什么是降级 / 降级优先？
> **降级**：主方案（大模型）不可用时，自动改用备选方案（规则引擎），保证功能不中断。
> 项目铁律："降级优先"——所有 AI 函数不抛异常，无 key 或失败时返回规则结果。148 条测试离线全过，就是降级的证明。
> 一句话："系统最重要的能力不是'多聪明'，而是'不会挂'。"

### 9. 什么是 BM25 / 信息检索？
> 给一批文档打分排序，找出与关键词最相关的文档。BM25 根据"词出现频率 + 文档长度"计算相关度。我们是中文场景，所以先用 jieba 分词再检索。

### 10. 什么是状态机？
> 对象在不同"状态"之间按规则迁移。项目的面试状态：`待开始 → 进行中 → 已完成/已放弃`。状态不对就不允许操作（如已完成不能再答题），保证数据一致。

### 11. 什么是 CDN / 无构建工具？
> **CDN**：把 JS/CSS 放在公开服务器上供浏览器加载。我们把 Vue/Bootstrap 文件下载到本地 `frontend/static/vendor/`，这样断网也能用。
> **无构建工具**：不用 npm/webpack，不用编译，浏览器直接加载源文件。好处是部署简单、离线可跑；代价是不能用复杂工程化特性——对答辩演示来说完全够用。

### 12. 什么是 Mock 数据？
> 后端接口还没好时，前端先用假数据（写死的 JSON）开发界面，保证前后端可并行。接口就绪后切真实接口。我们前期用 Mock 兜底，联调时切换为真实 API。

### 13. 什么是统一响应格式 / 接口契约？
> 所有接口统一返回 `{code: 0, message: "success", data: {...}}`：code=0 成功，非 0 是业务错误码。前端写一套解析逻辑即可通吃所有接口。这属于"接口契约"——前后端提前约定好的规矩，避免联调返工。

## 四、如果评委追问"为什么这么设计"，三个万能答案

1. **"为了可演示 / 离线可用"**：前端本地化、AI 可降级、知识库 BM25 离线——答辩演示对稳定性要求高。
2. **"为了可维护 / 可扩展"**：分层架构 + 统一响应 + ORM 抽象，每层可独立替换，数据层可迁移。
3. **"为了可解释 / 可测试"**：评分锚定知识库要点、证据链可追溯、148 条自动化测试兜底——答辩最怕"说不清"。
