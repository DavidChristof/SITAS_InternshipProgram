## 1. 引言

### 1.1 目的
定义系统的三类用户——**学生（候选人）、HR/教师、管理员**——各自的功能范围与操作流程，作为前端身份门面改造（方案A）和后续接口鉴权（方案B）的需求依据，也作为文档组撰写《需求规约》的素材。

### 1.2 范围
- 只界定三类用户的功能边界与操作流程；
- 不涉及 AI 出题/评分/RAG 等核心算法逻辑（详见《项目基本信息.md》§3）；
- 面向**答辩演示**口径：三类身份进入系统后各自看到不同的功能入口，边界清晰可演示。

### 1.3 术语
| 术语 | 含义 |
|---|---|
| 学生 / 候选人 | 使用系统进行求职训练与面试的在校生 |
| HR/教师 | 使用后台进行招聘业务管理与教学评估的人员 |
| 管理员 | 系统全局管理者，负责后台全部数据与账号类管理 |
| 后台 | 面向 HR/教师、管理员的管理端（企业/岗位/候选人/面试官/题库/面试记录） |

---

## 2. 角色定义

| 角色 | 核心目标 | 典型场景 |
|---|---|---|
| **学生（候选人）** | 完成一次真实的模拟面试并获得评估 | 上传简历 → 选岗 → 与 AI 面试官对话 → 查看评分报告 |
| **HR/教师** | 维护招聘业务数据、观察候选人表现 | 维护企业/岗位/题库 → 查看候选人档案与面试记录 |
| **管理员** | 系统全局管理，维护面试官等账号类数据 | 管理全部后台数据、维护面试官、系统信息维护 |

---

## 3. 功能边界

### 3.1 学生（候选人）功能边界

| 功能 | 说明 | 关联页面 |
|---|---|---|
| 简历上传与解析 | 上传 PDF/DOCX/TXT，系统抽取姓名/邮箱/电话/教育/项目/技能等档案 | 候选人端·上传简历 |
| 岗位浏览 | 查看可投递岗位（含企业名、技能标签、描述） | 候选人端·岗位大厅 |
| 创建并开始面试 | 选中岗位 → 系统生成 5 环节问题（自我介绍/项目深挖/专业能力/行为面试/反问） | 候选人端·岗位大厅 → 面试对话 |
| 逐题作答与评分 | 文字或语音回答，实时获得评分与反馈，进入下一题 | 面试对话 |
| 查看结果报告 | 总分/等级/5 维雷达图/优缺点/改进建议/逐题复盘 | 结果报告 |
| 历史记录 | 查看本人历次面试状态与总分 | 候选人端·历史记录 |

**学生不可见**：后台所有管理功能（企业/岗位/候选人/面试官/题库/面试记录）。

### 3.2 HR/教师 功能边界

| 功能 | 说明 | 关联页面 |
|---|---|---|
| 企业管理 | 新增/编辑/删除企业（名称/行业/描述） | 后台·企业 |
| 岗位管理 | 为岗位挂靠企业、维护描述/要求/技能 | 后台·岗位 |
| 题库管理 | 按岗位与环节维护面试题目（问题/要点/样例） | 后台·题库 |
| 候选人管理 | 查看候选人档案（简历解析画像），维护候选人 | 后台·候选人 |
| 面试记录 | 筛选（状态/岗位/候选人）查看面试记录，进入详情看报告与逐题复盘 | 后台·面试记录 |

**HR/教师不可见**：面试官管理、系统管理（管理员专属）。

### 3.3 管理员功能边界

在 HR/教师全部功能之上，额外包含：

| 功能 | 说明 | 关联页面 |
|---|---|---|
| 面试官管理 | 新增/编辑/删除面试官（姓名/角色/头衔）；面试可**指定归属面试官**（对话页/报告展示"AI 面试官：张老师"） | 后台·面试官 |
| 系统管理 | 系统信息维护、身份入口说明、数据概览（简单版） | 后台·系统管理 |
| 数据治理 | 全量后台数据的最终维护与删除 | 后台·各管理页 |

## 5. 操作流程

### 5.1 学生（候选人）完整闭环

```
进入系统 → 选择「学生」身份
   ↓
上传简历（姓名/邮箱/文件） → 系统解析生成候选人档案
   ↓
进入岗位大厅 → 浏览岗位 → 点击「开始面试」
   ↓
系统创建面试 → 进入 AI 面试对话
   ↓
逐题作答（文字/语音）→ 每题获得评分与反馈 → 进入下一题
   ↓
完成全部 5 环节 → 面试结束
   ↓
查看结果报告（总分/等级/雷达图/优缺点/建议/逐题复盘）
   ↓
历史记录页可随时回看既往面试
```

**关键规则**：必须先上传简历获得候选人身份，才能创建面试；面试按 5 个环节顺序作答，答完自动生成报告；**中途退出可随时从上次题目继续，也可主动放弃使记录作废**（状态机 pending → running → finished / abandoned）。

### 5.2 HR/教师 操作流程

```
进入系统 → 选择「HR/教师」身份
   ↓
进入后台（仅见：企业/岗位/题库/候选人/面试记录）
   ↓
① 维护企业（新增 → 编辑 → 删除）
   ↓
② 维护岗位（选择企业 → 填写描述/要求/技能）
   ↓
③ 维护题库（选择岗位/环节 → 录入题目/要点/样例）
   ↓
④ 查看候选人档案（简历解析画像）
   ↓
⑤ 查看面试记录（按状态/岗位/候选人筛选）→ 进入详情看报告与逐题复盘
```

**关键规则**：企业 → 岗位 → 题库 存在依赖关系（岗位须挂靠已存在企业）；HR/教师看不到面试官管理与系统管理入口。

### 5.3 管理员操作流程

```
进入系统 → 选择「管理员」身份
   ↓
进入后台（全部 7 个入口：企业/岗位/候选人/面试官/题库/面试记录/系统管理）
   ↓
维护面试官（新增/编辑/删除）→ 维护后台全部业务数据
   ↓
进入系统管理（身份入口说明、数据概览）
```

**关键规则**：管理员拥有全部后台权限；面试官管理为管理员专属。

## 6. 与现有系统的映射

| 角色 | 前端视图 | 后端接口 |
|---|---|---|
| 学生 | 候选人端（岗位大厅/上传简历/历史）→ 面试对话 → 结果报告 | `/api/candidate/*`、`/api/interview/*` |
| HR/教师 | 后台（企业/岗位/题库/候选人/面试记录 5 页） | `/api/admin/{enterprises,jobs,questions,candidates,interviews}` |
| 管理员 | 后台（上述 5 页 + 面试官管理 + 系统管理） | `/api/admin/{interviewers}` 等 |

> 现有后端接口对三角色无鉴权差异（统一开放），本期边界由**前端身份选择 + 菜单隔离**保证；接口级鉴权为方案B 后续项。
> 面试官名册 → 面试归属：候选人选岗时可指定本次面试官，面试对话页与报告展示"AI 面试官：张老师（实习指导教师）"，让名册数据产生实际业务意义。

## 7. 边界与约束

1. **实现层级**：本期为展示层隔离（localStorage 记录身份，前端按角色渲染导航/菜单），不涉及后端权限校验。
2. **数据安全**：真正的接口鉴权（防绕过前端直接调用 API）需要方案B 落地 users 表 + role 校验，本期不实现，作为答辩加分项。
3. **管理员系统管理**：简单版即可（身份说明 + 数据概览），不引入复杂权限模型。
4. **验收口径**：三类身份分别进入，能看到/看不到的功能与 §4 矩阵一致即可。
5. **面试官归属与登录演进**：`interviewers` 表定位为"教师名册"，面试创建时可指定归属面试官（对话页/报告展示"AI 面试官：张老师"）。真正的**账号登录 + 身份校验 + 数据隔离**（张老师登录后只能管理自己的面试）为方案B 后续项，本期不做，答辩口径以此为准。

---

## 8. 验收标准

1. 进入站点先选择身份，选择后进入对应入口，刷新后身份保持；
2. 学生身份：仅见候选人端，无后台入口；
3. HR/教师身份：后台仅见 5 个业务页（无面试官管理）；
4. 管理员身份：后台 7 个入口全部可见；
5. 三类身份下候选人面试闭环（选岗→面试→报告→历史）回归正常。
