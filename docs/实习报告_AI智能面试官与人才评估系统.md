## 一、引言

随着大语言模型技术的快速发展，AI 正从内容生成走向具体业务的深度落地，招聘与人才评估是其中极具价值的应用场景。校园招聘中，求职者缺乏低成本、可反复练习的面试训练方式，用人方也缺少标准化的能力评估手段。面向这一痛点，本次实习的选题为"AI 智能面试官与人才评估系统"，目标是构建一个能够模拟真实面试流程、自动出题、逐题评分并生成评估报告的系统，覆盖大学生求职训练、校园招聘模拟与岗位能力评估三类场景。

本人在项目中担任项目组长，并负责系统的 AI 核心与知识库检索模块。实习期间，本人参与了从需求分析、技术选型、核心算法实现、前后端联调到测试交付的完整研发流程，深入实践了大模型应用、检索增强生成（RAG）与 Agent 化编排等前沿技术。现将实习过程、成果与心得体会做详细总结。

## 二、实习基本信息

### 2.1 实习项目概况

本项目为五人小组共同开发的"AI 智能面试官与人才评估系统"。五人各司其职、协作开发：成员A（本人）负责 AI 核心与知识库检索、总体架构与需求分析；成员B 负责业务后端接口、数据库模型与面试状态机；成员C 负责前端候选人端（岗位大厅、面试对话、结果报告）与身份门面；成员D 负责前端后台管理页、Mock 数据兜底与测试用例设计；成员E 负责数据初始化、简历解析接口联调、冒烟测试与演示材料。系统的核心闭环为：简历上传 → 简历解析 → 岗位选择 → 知识库（BM25）检索 → AI 生成问题 → 候选人逐题回答 → AI 追问与评分 → 生成面试报告 → 保存面试记录。系统覆盖了大模型、RAG、Agent、前端交互与后端管理等多个模块，实现了从简历投递到能力评估的全链路自动化。技术栈采用 FastAPI + SQLite + SQLAlchemy 构建后端，以 DeepSeek 大模型作为 AI 核心，基于 jieba 分词与 BM25 算法构建离线检索知识库，前端使用 Vue3（CDN）与 Bootstrap，不依赖 Node 构建工具，保证离线环境下仍可完整演示。

### 2.2 实习时间与地点

本次实习时间为 2026 年 8 月 2 日至 8 月 29 日，共四周。实习地点位于四川省成都市，实习单位为四川华迪信息技术有限公司。实习期间本人严格遵守企业的考勤制度与开发规范，按时到岗、认真投入项目研发，与团队成员密切配合，确保项目按计划推进。

### 3.2 实习任务

本人承担的主要任务包括：

第一，实现系统 AI 核心模块，包括简历解析与岗位画像、五环节面试编排、结构化追问、逐题评分与报告生成；第二，建设岗位与面试题知识库，支持岗位说明、企业资料、常见题库、评分标准与优秀回答样例的检索；第三，封装大模型调用并实现招聘数据 SQL Agent、语音转写工具，且保证无 API Key 时系统自动降级、演示闭环始终可用；第四，编写三类用户的功能边界与操作流程需求文档；第五，主导前后端联调与验收，保障 148 项自动化测试全部通过。

## 四、实习内容与过程

### 4.1 技术栈选型与整体架构设计

项目初期，团队围绕后端框架、AI 模型接入与前端方案进行了充分的技术选型。后端采用 FastAPI 与 SQLAlchemy 2.0、SQLite、Pydantic v2，理由是其异步性能好、类型校验完善、文档自动生成，适合快速迭代的 AI 应用；AI 核心接入 DeepSeek 大模型，通过 OpenAI 兼容 SDK 统一封装，并将所有密钥放在环境变量中管理。前端采用 Vue3（CDN）与 Bootstrap 5，不引入 Node 构建工具，静态资源全部本地化，保证演示现场无外网也能运行。

在架构设计上，系统分为 API 层、服务层、知识库层与前端展示层。API 层由团队成员负责，统一返回 `{code, message, data}` 格式；服务层为 AI 核心，承载全部大模型调用与算法逻辑；知识库层通过 jieba 分词 + BM25 实现离线检索；前端按角色隔离展示。本人负责服务层与知识库层的设计与实现。

### 4.2 AI 核心模块开发

#### 4.2.1 简历解析与岗位画像模块

简历解析是本项目的入口环节。本人设计了"规则提取 + 大模型融合"的两段式方案：先用规则引擎从简历文本中抽取姓名、邮箱、教育经历、技能关键词、经验年限等结构化信息，保证基础字段在无模型的情况下也能准确识别；再调用大模型对信息做语义增强与补全，最后将规则结果与模型结果合并去重，生成候选人档案。同时实现了岗位画像模块，从岗位描述中提炼能力维度、核心技能、考察重点与建议环节，为后续出题提供依据。该模块在无 API Key 时会自动降级为纯规则解析，保证功能闭环不中断。

#### 4.2.2 RAG 知识库与检索增强模块

按照任务书要求，本人建设了覆盖岗位说明、企业资料、常见题库、评分标准、优秀回答样例五类文档的离线知识库。知识库使用 jieba 中文分词与 BM25 稀疏检索算法构建索引，支持在服务启动时幂等重建。面试出题时，系统先根据岗位画像与简历素材构造检索词，从知识库中检索最相关的题目与资料片段，将检索结果作为"证据链"提供给大模型，使每道题目、每轮评分与每条反馈都有据可查，显著提升了回答的针对性与可解释性。实习后期本人还将题库从 17 道扩充至 49 道，企业资料与优秀回答样例同步扩充，使知识库覆盖五个演示岗位的完整面试环节。

#### 4.2.3 AI 面试 Agent 编排

面试编排是本项目的核心，也是任务书强调的 Agent 实现。本人设计并实现了五环节的结构化面试流程：自我介绍、项目深挖、专业能力、行为面试、反问。为每个环节编写了独立的提示词模板，实现以下能力：一是自动出题（`plan_interview`），结合岗位画像、简历素材与知识库检索，按环节生成问题序列并确定考察要点；二是结构化追问（`generate_followup`），根据候选人回答质量生成有明确原因的下一个问题，深入挖掘真实能力；三是逐题评分（`evaluate_answer`），按照"要点命中 + 回答完整度"的规则给出 0-100 分与改进建议；四是报告生成（`generate_report`），聚合各环节得分，输出总分、等级、五维能力雷达图数据、优缺点、录用建议与逐题复盘。整个流程以状态机控制推进，具备"感知—规划—行动—评估—总结"的 Agent 化特征。

#### 4.2.4 工具调用与降级优先设计

除面试编排外，本人还实现了两个 Agent 工具：一是招聘数据 SQL Agent，支持用自然语言查询招聘数据库，设计了表白名单与 SQL 注入防护（仅允许 SELECT 指定表、拦截堆叠语句与危险关键字），在无模型时也有关键词规则兜底；二是语音转写工具，采用可选加载的 faster-whisper 模型，任何失败场景都返回空串而非抛异常。降级优先是本项目贯穿始终的工程铁律：所有 AI 服务函数在无 API Key 或调用失败时自动降级为规则结果，保证端到端闭环始终可演示。本人也通过这一原则深刻体会到，面向演示与交付的系统，稳健性与可用性比算法华丽更重要。

### 4.3 面试状态控制与流程完善

为了让面试流程更完整、更贴近真实，本人主导完善了面试状态机与流程能力：状态机覆盖 `待开始 → 进行中 → 已完成 / 已放弃` 四种终态；候选人中途退出后可从上次题目继续作答（新增面试状态查询接口）；面试过程中也可主动放弃使记录作废；候选人选岗时可指定本次面试官，对话页与报告均展示"AI 面试官"归属。这些能力在答辩演示与功能完整性上均有明显价值。

### 4.4 需求分析与文档工作

按照任务书第一条要求，本人编写了《需求分析——三类用户的功能边界与操作流程》文档，明确了学生、HR/教师、管理员三类用户各自的功能范围与操作流程，并以功能权限矩阵的形式界定边界，同时输出了岗位与面试题知识库、分工方案、项目各阶段成果记录等多份文档，作为项目交付与后续文档组整理素材的依据。

### 4.5 五人分工协作与联调验收

项目采用五人分工、固定功能分支、代码评审与统一接口契约的协作模式。五人分别承担明确职责：成员A（本人，组长）负责 AI 核心与知识库检索、总体架构与需求分析；成员B 负责业务后端接口、数据库模型与面试状态机；成员C 负责前端候选人端与身份门面；成员D 负责前端后台管理页、Mock 数据兜底与测试用例设计；成员E 负责数据初始化、简历解析接口联调、冒烟测试与演示材料。各成员按照目录所有权约定开发，避免代码互相覆盖，功能完成后通过代码评审合入主分支。

本人作为组长，除完成 AI 核心模块外，还牵头协调五人进度、对齐接口契约。联调阶段，本人推动前端从 Mock 数据切换至真实接口，修复了报告页雷达图绘制时序等问题，对齐了接口返回格式，并反复跑通"上传简历→选岗→面试→报告"的完整闭环。协作过程中，本人也深刻体会到五人分工下清晰接口契约与及时沟通对团队效率的关键作用。

## 五、实习工作成果

### 5.1 功能成果

经过四周的实习，本人参与的 AI 智能面试官与人才评估系统完成了从简历解析到评估报告的全链路闭环。系统支持学生上传简历生成候选人档案、浏览岗位并开始面试，AI 面试官按五个环节自动出题、逐题评分反馈并生成包含总分、等级、五维雷达图、优缺点与录用建议的完整报告；支持中途退出后续接与主动放弃作废；支持候选人在选岗时指定面试官；后台支持企业、岗位、候选人、面试官、题库与面试记录六类业务对象的完整管理，并按三类身份隔离功能入口。

### 5.2 技术成果

在技术层面，本人实现了对大模型调用的健壮封装（超时、重试、JSON 结果容错解析），编写了五个环节的提示词模板；构建了基于 jieba + BM25 的离线 RAG 知识库并实现了证据链机制；实现了具备出题、追问、评分、报告能力的面试 Agent 编排；实现了带安全校验的 SQL Agent 与可降级的语音转写工具；构建了"无 API Key 全链路规则降级"的保障机制，使系统在完全离线的环境下也能完整演示。

### 5.3 测试与质量指标

本人推动建立了覆盖简历解析、岗位画像、出题、追问、评分、报告、SQL Agent 安全校验、知识库检索、后台 CRUD、候选人端接口、面试状态机与联调冒烟的测试体系，共 148 项自动化测试全部通过，且全部可在无 API Key 的离线环境下运行，直接验证了降级设计的正确性。联调阶段还定位并修复了反问环节评分引用字段错误、报告雷达图绘制时序等若干问题。

### 5.4 协作贡献

作为组长，本人牵头完成了需求分析文档、三类用户功能边界定义与接口契约对齐；推动前端 Mock 数据切换为真实接口并完成全链路联调验收；组织各成员按目录所有权协作开发，避免代码互相覆盖，确保项目按计划交付。同时主动将知识库、面试流程等环节的文档整理归档，为项目交付与答辩展示提供了完整的材料支撑。

## 六、实习总结与心得体会

### 6.1 实习总结

本次在四川华迪信息技术有限公司参与 AI 智能面试官与人才评估系统开发的实习，是本人职业发展中的一次重要历练。通过四周时间，本人完整地参与了一个企业级 AI 应用从需求分析、技术选型、核心实现到联调交付的全过程，既在技术上深入掌握了大模型应用、RAG 与 Agent 编排，也在工程实践上建立了降级优先、测试驱动、文档先行的习惯，更重要的是在团队协作中提升了自己的沟通与协调能力。这段经历让本人认识到，一个真正"能用"的 AI 系统，不仅取决于模型能力，更取决于工程化的质量保障。

### 6.2 心得体会

#### 6.2.1 理论与实践的差距：在实践中深化理解

在学校学习大模型与算法时，往往停留在概念与简单示例层面，而真实项目中需要考虑调用超时、返回格式异常、接口不稳定、无 Key 环境等一系列现实约束。例如 RAG 在课堂上只讲"检索增强"的概念，而落地时本人需要设计分词、索引重建、证据链传递与检索噪声控制等完整链路。这些只有通过实践才能真正理解。这也让本人认识到，动手解决真实问题是深化理论理解的最佳途径。

#### 6.2.2 降级优先的工程思想：稳健性比炫技更重要

本项目最重要的工程原则是"降级优先"——所有 AI 服务在无 Key 或失败时都自动降级为规则结果。起初本人觉得这是妥协，但 148 项测试全程离线跑通、演示永不中断的事实让本人认识到：面向真实交付的系统，可用性永远排在第一位。能优雅降级的系统，比华而不实的算法更有价值。这一思想将长期影响本人今后的开发实践。

#### 6.2.3 团队协作与接口契约：跨角色沟通是成功关键

作为组长，本人深刻体会到多人协作中"接口契约先行"的重要性。前后端若不先约定统一的响应格式与字段语义，联调阶段必然反复返工。通过固定分支、代码评审、文档归档与及时沟通，团队避免了代码互相覆盖，保证了集成质量。本人在沟通协调、进度推进方面的能力也在这次实习中得到明显提升。

#### 6.2.4 大模型与 RAG 的工程化落地：把"能跑"变成"好用"

将大模型能力真正工程化，需要把提示词、检索、状态机、工具调用、降级机制等要素组织成可靠的系统。本次实习让本人明白，"能跑通 Demo"与"能稳定交付"之间隔着完整的工程化：健壮解析、可解释的证据链、可复现的评分、可维护的文档，缺一不可。这也是本人未来深耕大模型应用工程的方向。
